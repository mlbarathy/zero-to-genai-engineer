First fork in the road

You can fix “missing facts” with RAG too.
Fine-tuning is for a different job.

Same return-policy question. Two different tools.

RAG

At answer time, search your PDF/wiki, paste the matching text into the prompt, ask the frozen model.

Changes: what the model sees right now (fresh facts).
Does not change: the model’s weights.

Fine-tuning

Train on your past chats so the model picks up your tone, format, and habits.

Changes: how the model behaves.
Weak at: facts that change every week (you would retrain).

Return policy text that changes often → start with RAG. Brand voice and short WhatsApp-style replies that stay the same → fine-tune. Real products often use both: RAG for today’s facts, fine-tune for manners.

PEFT · worked example

Count the numbers. That is all PEFT is.

Imagine one tiny layer with a 4×4 weight matrix. Full fine-tuning touches every cell. PEFT freezes those 16 cells and trains only a small adapter.

ApproachWhat you trainCount
Full fine-tuneAll of W (4×4)16
PEFT (tiny adapter)Adapter only (example size 4)4
SavingsFrozen W never gets gradients75% fewer trainable params
Same idea at real scale: a 7B model has 7,000,000,000 weights. PEFT might train ~20–50 million (under 1%). Formula: trainable_PEFT ≪ N_full. LoRA is one way to build that small trainable set.

LoRA

LoRA idea: don’t store the whole ΔW.
Store two thin pieces that multiply into it.

LoRA = Low-Rank Adaptation. Freeze W₀. Learn B and A only. The update is B × A.

Rule: each cell of ΔW is one number from B times one number from A.

ΔW[i, j] = B[i] × A[j]

Why this saves money

Same trick on a real layer size.

Now d is big and r stays small. For a 512×512 weight matrix with rank r = 8:

What we storeShapeNumbers
Full ΔW512 × 512262,144
LoRA B512 × 84,096
LoRA A8 × 5124,096
LoRA totalB + A8,192 (about 3%)
Formula to remember: trainable ≈ 2 × d × r, not d × d. Bigger layers, bigger savings. Paper: Hu et al. 2021.

Quantization · the point

We are not teaching the model new facts here.
We are storing the same weights with fewer bits.

Goal: fit a big frozen base on a small GPU so QLoRA training is possible.

Rule: memory ≈ N × (bytes per weight).
7B × 2 bytes ≈ 14 GB.
7B × 0.5 bytes ≈ 3.5 GB.
Trade: a little rounding error. Gain: the model fits. That is the whole reason quantization appears before QLoRA.

QLoRA · worked example

Same 7B model. Do the memory arithmetic.

Memory ≈ (number of parameters) × (bytes per parameter). That one line explains why QLoRA fits on Colab.

SetupBytes / param7B size
Base in FP16 (LoRA case)27e9 × 2 = 14 GB
Base in NF4 (QLoRA case)0.57e9 × 0.5 = 3.5 GB
LoRA adapters (example 24M)2 (FP16)24e6 × 2 ≈ 0.05 GB
QLoRA total (weights only)NF4 base + FP16 adapters≈ 3.55 GB
What trains? Only the adapters (~24M). The 7B NF4 base is frozen.
What is “Q”? Quantized base. What is “LoRA”? The B and A adapters on top.
Forward pass idea: dequantize a weight block to 16-bit just long enough to multiply, then keep storing it as 4-bit.
How the words fit

Three names. One family.

1
PEFTThe family name: freeze the big model, train a small add-on.
2
LoRAThe popular PEFT method: the add-on is two thin matrices B and A.
3
QLoRALoRA plus a 4-bit compressed base, so it fits on a small GPU.
If someone says “we fine-tuned with QLoRA,” they mean: quantized base + LoRA adapters. Not a totally different algorithm from LoRA.
